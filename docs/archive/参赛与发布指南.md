## 二、小程序怎么发布和测试

在 WorkBuddy 内有完整的发布通道，不需要自己去装微信开发者工具：

1. **创建应用**：把小程序项目（含 `app.json` + `pages`）放在一个目录里，用「发布为应用」发布——系统识别出小程序项目后，会自动创建对应的小程序应用并注册该项目（这一步没有链接产生，小程序本身就没有 URL）。
2. **发布上线**：打开该小程序应用的预览面板，点右上角「**分享**」→「发布小程序」。绑定账号扫码（**体验版不需要 AppID** 即可起步）、上传代码、提交审核、发布，全在 WorkBuddy 内完成。
3. **测试**：
   - 体验版：绑定后生成体验二维码，手机微信扫码即可真机测试核心功能；
   - 正式发布需要小程序账号（mp.weixin.qq.com 注册，个人主体可申请），提醒类工具类目、订阅消息模板都要在后台配置。
4. 注意：审核时间不可控（通常几小时到 1-2 天），这也是截稿前不建议临时转小程序的原因。

## 三、小程序怎么在手机上提醒用户

先说清一个硬限制：**小程序不能后台常驻**，手机锁屏或切走后页面 JS 被挂起，网页版那套"页面内闹铃"在小程序里不可靠。可行的方案按推荐度排序：

| 方案 | 原理 | 限制 |
| --- | --- | --- |
| **订阅消息（推荐）** | 设置提醒时 `wx.requestSubscribeMessage` 请求授权 → 云端定时任务到点调 `subscribeMessage.send` → 微信「服务通知」推送（横幅+震动，锁屏也能收到） | 一次性订阅：**一次授权只能发一条**；长期订阅仅政务/医疗/教育等特定类目开放，工具类拿不到。变通：一次请求可同时勾选多个模板累积条数；或每次设提醒都请求一次授权（用户勾「总是保持以上选择」后无感） |
| 前台提醒 | 小程序开着时用定时器检查 + `wx.vibrateShort` 震动 + 页面内全屏提醒 + 铃声 | 只在用户正看着手机时有效，锁屏无效 |
| 列表兜底 | 提醒列表带倒计时 | 不保证准时弹出，只是记录 |

结论：小程序版要做到「到点就响」，**必须有服务端**（云开发的定时触发器或自建 cron + 消息推送）。WorkBuddy 云服务可以承担存储和定时任务。网页版（当前实现）反而是「打开页面就响」体验最好的轻量形态。

## 四、语音输入怎么办

**最推荐的方案就是你说的：输入法语音键（零开发）。** 微信输入法、豆包输入法、讯飞输入法的语音识别质量都很高，且是系统级能力——在网页的输入框和小程序的 `<input>` 里都直接可用。用户按住语音键说「明天9点交电费」，文字落进输入框，后面的时间解析自动接管。本应用"一句话输入"的设计天然适配这条路，不需要写任何代码。

**已补充的进阶能力**（本次已实现）：网页版加了麦克风按钮——
- 支持浏览器语音识别（Web Speech API）的 Chrome/Edge 会显示麦克风，点击说话、松手自动转文字并实时预览解析结果；
- Safari/Firefox 或不支持的设备上按钮自动隐藏，不影响任何人；
- 识别服务连不上时（国内网络环境可能发生），会提示改用输入法语音键，不会卡死。

**小程序版的升级玩法**：微信官方「同声传译」插件（WechatSI）提供 `wx.getRecordRecognitionManager`，可以做"按住说话 → 实时转文字"，体验更像语音助手；插件免费，需在小程序后台添加。
